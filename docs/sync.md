# 飞书知识同步与晓多文件导入

`kb-sync once` 把飞书多维表格中已启用的 SKU 和问答发布到知识服务。`kb-sync watch` 持续执行相同的核对。晓多数据先通过店铺后台导出，整理成 CSV 或 JSONL，再用 `kb-sync import-xiaoduo` 写入飞书的原始问答列。

## 准备飞书数据

1. 在同一个飞书多维表格中准备 SKU 表和问答表，也可以只配置其中一张。取得多维表格的 `app_token` 和每张数据表的 `table_id`。如果拿到的是知识库页面链接，先确认它所指向的多维表格与实际 Base 令牌。[飞书多维表格元数据](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app/get)
2. 使用飞书企业自建应用，为同步开通字段列表和记录列表的读取权限，并令该应用可以读取配置表里的全部目标记录与列。执行晓多导入的应用另外需要问答表的新增、更新记录权限。高级权限可以单独限制行和列。[飞书多维表格接口及权限](https://open.feishu.cn/document/agile-project-cycle-management-based-on-bitable/introduction)
3. 复制 [字段映射示例](../deploy/tables.example.json)，替换两处 `table_id`，将 `fields` 中的中文值改成表中的实际列名。配置中出现的每一列都必须存在。没有使用的可选列可以从映射中删去。晓多导入时使用 `name` 指定目标表。

| 映射键 | 飞书字段与填写方式 |
| --- | --- |
| `shop` | 店铺稳定标识，文本或单选。与知识服务给店铺令牌配置的店铺标识一致。 |
| `id` | 一条知识记录的稳定标识，文本或单选。相同店铺里的 SKU 和问答须使用不同的记录标识；不同店铺可以复用相同标识。 |
| `product_ids` | 关联的平台商品 ID。文本列可以填一个 ID，例如 `000728`，或 JSON 字符串数组，例如 `["000728","000729"]`。也可使用飞书多选列，每个选项填一个商品 ID。 |
| `scope` | 文本或单选。示例中的“商品”表示只适用于列出的商品，“店铺”表示适用于本店所有商品。SKU 必须用商品范围，店铺范围只适用于问答，且其商品 ID 列必须为空或为 `[]`。 |
| `enabled` | 示例采用复选框，勾选即可发布。也支持文本或单选，默认认可 `enabled`、`true`、`启用`、`已启用`。使用其他名称时，可在对应表配置中加 `"enabled_values": ["已审核发布"]`。标签按原文精确匹配。 |
| `sku`、`model` | 商品规格编码和型号，建议用文本列；SKU 表至少映射其中一个。数值型编码在录入时就可能失去前导零。 |
| `question`、`answer` | 问答表的原始问题、原始答案，使用文本；两项都必须映射。SKU 表也可映射 `answer` 作为商品说明。 |
| `question_override`、`answer_override` | 可选的人工审核文本列，分别覆盖对应的原始列。人工列留空时使用原始值。 |
| `source` | 可选的来源文本或超链接列。留空时同步器生成指向该行的飞书链接。 |

例如，店铺 `demo` 的 SKU 记录使用 `id=sku-001` 和 `product_ids=["000728"]`，问答使用其稳定原始标识 `id=qa-09` 和同一商品 ID。这两条记录通过店铺和平台商品 ID 关联。上线前检查平台商品 ID、SKU 编码与飞书行 ID 所在的列。飞书原生关联记录列、公式结果或带多个 ID 的逗号分隔文本，应先整理成上表支持的商品 ID 列。查询时使用**平台商品 ID**。

同步器读取映射列里的文本。若答案存在单独的飞书文档或 Wiki 页面，需要先把可回答的正文放入问答列，原链接填入来源列；程序保留链接供查证，不下载或解析链接目标、图片或附件。作用范围不明、启用状态不明、商品范围缺少商品 ID、店铺范围含商品 ID，或问答缺少正文的记录会退出发布集。已经发布的记录出现这些情况时，下一次成功同步会将其撤下。

## 配置与运行

| 环境变量 | 用途 |
| --- | --- |
| `FEISHU_APP_ID`、`FEISHU_APP_SECRET` | 自建应用 ID 和密钥，用于取得租户访问令牌。 |
| `FEISHU_BASE_TOKEN` | 配置表所属的多维表格 `app_token`。 |
| `KB_TABLES_JSON` | JSON 数组的**内容**。每张表一项，示例见上文。 |
| `KB_ADMIN_TOKEN` | 与 `kb-api` 一致的管理令牌。单独导入文件到飞书时不需要。 |
| `KB_API_URL` | 知识服务根地址，默认 `http://127.0.0.1:8080`。支持 HTTPS 和回环地址 HTTP。同步器自行添加管理接口路径。 |
| `KB_SYNC_DB` | 可持久化的 SQLite 文件，默认 `data/kb-sync.sqlite3`，相对于进程启动目录。定时运行时宜设置为固定绝对路径。 |
| `KB_POLL_SECONDS` | 每轮完成到下一轮开始的等待秒数，默认 60，允许 1–86400。 |

下面的 PowerShell 命令在仓库根目录执行。先将配置副本 `deploy/tables.local.json` 替换为真实表的映射，并通过部署环境提供以上应用凭据和管理令牌。

```powershell
$env:KB_TABLES_JSON = Get-Content -Raw -Encoding utf8 .\deploy\tables.local.json
cargo build --release --locked --bin kb-sync
.\target\release\kb-sync.exe once
```

启动 `kb-api` 后运行 `once`。例如，`answers: 98 published entries, 2 changes` 表示该表当前发布集有 98 条，本次提交了 2 项变更。用店铺令牌按一个已知商品 ID 验证可查到预期 SKU 和问答，再启动持续同步。

```powershell
.\target\release\kb-sync.exe watch
```

`watch` 启动时先同步，再等待。每次读取所有配置表的全部页，变更可见时间包含等待时间、扫描时间和提交时间。读取其他表发生错误时，已经完成的表仍可独立更新。

### 可选的飞书记录变更通知

要在修改记录后提前唤醒 `watch`，可给同步进程设置下列变量，再启动它。默认只轮询，不监听事件端口。

| 环境变量 | 设置方法 |
| --- | --- |
| `FEISHU_EVENT_BIND` | 填监听地址，例如 `127.0.0.1:8081`，使用独立端口。前端 HTTPS 代理将公开的 `POST /feishu/events` 转发到该地址的同名路径。 |
| `FEISHU_VERIFICATION_TOKEN` | 飞书应用「事件与回调 → 加密策略」中的 Verification Token，开启事件监听时必填。 |
| `FEISHU_ENCRYPT_KEY` | 在飞书启用加密策略时，填入同一 Encrypt Key。同步器支持加密验证请求和记录变更推送；未在飞书开启加密时，省略该变量。 |

1. 在应用后台选择将事件发送到开发者服务器，填写经过 HTTPS 代理的地址。代理应保留原始请求体和 `X-Lark-*` 签名请求头。地址验证通过后，添加 `drive.file.bitable_record_changed_v1` 事件，并完成所需权限审批与应用版本发布。[飞书事件接收 FAQ](https://open.feishu.cn/document/event-subscription-guide/event-subscriptions/faq?lang=en-US)
2. 通过飞书「订阅云文档事件」接口订阅目标 Base 文件，文件类型选择 `bitable`，确认订阅身份对该文件具备飞书要求的权限。同步器仅读取已配置的表，文件订阅由部署者在飞书完成。[订阅云文档事件](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/drive-v1/file/subscribe)
3. 在测试表改动一条已启用的记录，检查飞书事件投递日志、同步器的发布条数和店铺查询结果。响应 HTTP 200 表示接收器已经处理通知；数据在后续完整扫描成功时发布。

验证请求按飞书协议返回 challenge。普通事件要通过 Verification Token 和应用 ID 检查；启用加密时还会校验原始请求体签名、检查签名时间戳（前后 5 分钟）和解密 AES-256-CBC 数据。将同步主机时间与可靠时钟对齐。仅配置的 Base 和数据表的记录变更会唤醒同步。接收器不直接使用事件中的业务字段更新知识库，最近 4,096 个事件 ID 用于过滤重投，短时间内的多次修改合并为一次全量核对。单次请求体上限为 256 KiB，超限或漏投的事件由后续定时核对补齐。[飞书验签及解密说明](https://open.feishu.cn/document/event-subscription-guide/callback-subscription/receive-and-handle-callbacks)

## 从晓多导入

在已获授权的晓多机器人后台导出行业场景、自定义问题或精准意图，到任务中心下载。按导出字段把每条规则整理为一种明确的店铺、商品或商品集合适用范围。若原规则还以时间、订单阶段或上下文作为触发条件，应先由业务人员整理可独立使用的问答，再填写发布范围。请保留源记录的稳定标识；导出缺少稳定键时，需维护可长期复用的对应关系，保证同一条问答在下一次导入时仍能匹配。[晓多机器人操作手册](https://www.xiaoduoai.com/presales_bot_knowledge/5432)

输入文件使用 UTF-8，支持 CSV、JSONL 或 NDJSON，单文件最大 64 MiB。必需列为 `shop`、`id`、`scope`、`product_ids`、`question`、`answer`。可选列为 `sku`、`model`、`source`，应在目标表中映射。文件中的 `scope` 固定使用 `product` 或 `shop`；导入器会把它转换成表配置中相应标签列表的第一项。下面是仅含演示记录的 JSONL。

```jsonl
{"shop":"demo","id":"qa-09","scope":"product","product_ids":["000728"],"question":"这款支持多大容量？","answer":"该型号支持 128 GB。"}
{"shop":"demo","id":"qa-10","scope":"shop","product_ids":[],"question":"如何联系人工客服？","answer":"请在店铺会话中发送“转人工”。"}
```

对于 CSV，单个商品可直接写文本 `000728`，多个商品使用标准 CSV 引号转义，例如单元格字面形式 `"[""000728"",""000729""]"`。同一文件出现重复的店铺和原始 ID 组合时，会在写入前报错。示例的问答表别名为 `answers`。

```powershell
.\target\release\kb-sync.exe import-xiaoduo answers .\xiaoduo.normalized.jsonl
```

导入先核对整个文件和现有飞书记录，再按 `(shop,id)` 新增或更新原始字段。导入期间若遇到网络或飞书写入错误，先前成功的行会保留，可以用同一份文件和同一份同步数据库重试。文件中未包含的已有记录会保留；可选列缺省时保留旧值，显式提供空字符串会清除对应原始值。已有人工覆盖和启用状态由飞书管理。新记录使用飞书表本身的默认状态；需要审核后上架时，把“已启用”复选框的默认值设为未勾选。用户随后在飞书勾选，下一轮同步才会发布。

## 删除核对与恢复

- 每轮分页和字段检查完成后，程序比较该表本次完整发布集和本地上次确认的发布集，通过管理接口原子提交该表的新增、修改和删除。按 Base 与 `table_id` 区分数据归属。失败页、缺少游标、记录 ID 重复、字段缺失或服务返回总数与扫描数不符，都会使本次表扫描停止，上次完整结果继续提供服务。
- **读取权限决定同步器看到的全量。** HTTP 拒绝会中止扫描；若飞书高级权限改变后返回一份成功但更小的可见列表，该列表会被当作完整结果，原先可见的行会被撤下。调整行级权限、适用范围标签或状态标签前，先停下 `watch`，用具备完整访问范围的应用确认表和字段，再恢复同步。成功返回空表时，该来源全部已发布记录都会撤下。
- 只从 `KB_TABLES_JSON` 移除一张表会停止扫描它；先前发布的数据会保留。要正常下线整表，保留其配置，在飞书撤下启用状态并完成一次成功同步，核对输出后再移除配置。把同一店铺的稳定记录键移交另一张表时，先同步原表撤下该键，再从新表发布。
- `KB_SYNC_DB` 保存数据归属、待发布批次和导入重试标识，与 `kb-api` 的数据库分别持久化。两者应配套备份与恢复。单独清空同步库会丢失已删除行的历史；单独重建服务库后原同步库可能判断数据已同步。重启使用同一个路径与同一服务地址，未收到成功确认的管理批次会先幂等重放。不同服务地址使用各自的同步库。
- `once` 在任一表失败时退出非零；`watch` 记录失败并按间隔重试。表级变更批次最多 50,000 条、32 MiB，超过时整批拒绝。对于首次发布的大表，可以在飞书分批启用，每次成功发布后再启用下一批。
- 生产中同一批知识使用一个同步状态库和单个写入者。单机进程通过状态库旁的文件锁避免重叠；有同步正在运行时，导入可能提示锁占用，等本轮结束再执行即可。
