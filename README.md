# 客服商品知识库

0.2.0 提供两种入口。客服打开站点首页，使用**自己的飞书账号**授权后，能浏览本人可见的 SKU、商品 QA 和晓多商品知识，并从记录出处进入飞书原表维护。业务应用也可以通过持有店铺密钥的后端，查询已同步到本机的知识索引，提前加载商品卡片。

| 组件 | 用途 |
| --- | --- |
| 个人网页版 | 服务用当前访客的短期用户令牌从飞书读取其可见的表、字段和记录。原表编辑由飞书按本人权限执行。 |
| `kb-api` | Axum / Tokio 接收查询。SKU 和机型走精确索引，中文问题走 Tantivy 全文索引。每个请求使用同一版本的店铺、商品和启用状态。 |
| `kb-sync` | 接收已授权的飞书记录变更通知，并定期逐表对账，发布增删改动；支持把已导出的晓多知识文件导入飞书指定原文字段。 |
| SQLite | 保存知识和发布版本。同步进度与待重试任务存入单独的数据库，服务重启可恢复。 |
| 可选 AI | 对两个同店商品先返回可引用的资料，再通过外部兼容接口流式返回比较结果。 |

## 接入与运行

- **服务器部署**见 [Linux 原生部署说明](docs/deploy.md)。初次安装可先启动 API，店铺密钥和飞书同步可以稍后开通。
- **网页授权及应用开发**见 [中文 API 指南](docs/api.md) 和 [OpenAPI 3.1](docs/openapi.json)。管理员配置一次飞书网页应用，访客只需在飞书官方页面确认授权。独立业务 API 另行绑定店铺密钥。
- **数据接入**见 [飞书同步与晓多导入](docs/sync.md) 和 [飞书字段映射示例](deploy/tables.example.json)。请按实际运营主库的字段和状态配置。
- **容量验证**见 [压测说明](docs/perf.md)。生产响应时间取决于实际数据、响应字节数、出口带宽与客服网络。

在装有 Rust 工具链及平台原生编译器的开发机，从仓库根目录执行：

```sh
cargo test --locked
cargo build --release --locked --bins
```

运行 `kb-api` 需要设置管理员密钥 `KB_ADMIN_TOKEN`。开发默认监听 `127.0.0.1:8080`，健康检查为 `GET /healthz`。生产原生安装使用 `127.0.0.1:8022`，由现有 HTTPS 代理提供公网入口。

Linux 发布包可在干净检出目录运行 `bash deploy/package.sh` 构建。归档和 SHA-256 校验值写入 `dist/`。
